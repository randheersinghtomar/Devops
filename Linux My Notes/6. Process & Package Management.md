<h1 align="center"> Process Management</h1>


### What is a Process?

A **process** is a running instance of a program.

Example:

```bash
nginx
````

When Nginx is running, Linux creates a process for it and assigns a **PID (Process ID)**.

---

### Types of Processes

#### 1. Interactive Process

A process started and controlled directly by a user.

Example:

```bash
vim test.txt
```

The process is connected to the user's terminal.

#### 2. System / Daemon Process

A process that runs in the background and provides system or application services.

Examples:

```text
sshd
cron
systemd
nginx
```

Daemon processes normally do not require direct user interaction.

#### 3. Automatic Process

A process that runs automatically based on a schedule, event, or system requirement.

Example:

```text
cron job
```

---

### Process States

| State | Meaning               |
| ----- | --------------------- |
| `R`   | Running               |
| `S`   | Sleeping              |
| `D`   | Uninterruptible Sleep |
| `T`   | Stopped               |
| `Z`   | Zombie                |

Check process state:

```bash
ps -ef
```

---

### PID & PPID

**PID (Process ID)**
Unique ID assigned to each process.

**PPID (Parent Process ID)**
PID of the process that created the current process.

Example:

```text
PID    PPID
2500   1200
```

Here, process `2500` was created by process `1200`.

## Static / One-Time Commands

### `ps`

`ps` displays information about currently running processes.

#### `ps`

```bash
ps
```

Shows processes associated with the current terminal.

#### `ps -a`

```bash
ps -a
```

Shows processes associated with terminals for all users, except processes that do not have a terminal.

#### `ps -u`

```bash
ps -u
```

Shows processes in a user-oriented format.

For a specific user:

```bash
ps -u ubuntu
```

#### `ps -x`

```bash
ps -x
```

Shows processes owned by the current user, including processes that do not have a controlling terminal.

#### `ps aux`

```bash
ps aux
```

Displays processes for all users in a detailed format.

Common fields:

```text
USER    PID   %CPU   %MEM   VSZ   RSS   STAT   START   TIME   COMMAND
```

#### `ps -ef`

```bash
ps -ef
```

Shows all processes in full-format listing.

Example:

```bash
ps -ef | grep nginx
```

#### `ps -e`

```bash
ps -e
```

Shows all processes.

`-e` means **every process**.

#### `ps -eo`

Allows you to specify the fields you want to display.

```bash
ps -eo pid,ppid,user,stat,cmd
```

Example:

```text
PID   PPID USER     STAT CMD
1     0    root     S    /sbin/init
1200  1    root     S    sshd
1250  1200 ubuntu   S    bash
```

#### Count Processes

```bash
ps -e | wc -l
```

`ps -e` lists all processes and `wc -l` counts the lines.

#### `echo $$`

```bash
echo $$
```

Displays the **PID of the current shell**.

Example:

```text
ubuntu@server:~$ echo $$
1250
```

Here, `1250` is the PID of the current Bash shell.

---

### `ps -f` Field Description

```bash
ps -f
```

Example:

```text
UID      PID   PPID  C  STIME  TTY      TIME     CMD
ubuntu  1250   1200  0  18:20  pts/0    00:00:00 bash
```

| Field   | Description                          |
| ------- | ------------------------------------ |
| `UID`   | User who owns the process            |
| `PID`   | Process ID                           |
| `PPID`  | Parent Process ID                    |
| `C`     | CPU utilization value                |
| `STIME` | Process start time                   |
| `TTY`   | Terminal associated with the process |
| `TIME`  | CPU time used by the process         |
| `CMD`   | Command used to start the process    |

---

### `pgrep`

Finds PID(s) of a process using its name or pattern.

```bash
pgrep nginx
```

Example:

```text
1250
1260
```

---

### `pidof`

Displays PID(s) of a specific running program.

```bash
pidof nginx
```

Example:

```text
1250 1260
```

---

### `pstree`

Displays processes in a parent-child tree structure.

```bash
pstree
```

Example:

```text
systemd
 ├─sshd
 │  └─bash
 │     └─sleep
 └─cron
```

---

### `kill`

`kill` is used to send a signal to a process.

Syntax:

```bash
kill [signal] PID
```

#### `kill -l`

Lists available signals.

```bash
kill -l
```

Common signals:

```text
1   SIGHUP
2   SIGINT
9   SIGKILL
15  SIGTERM
20  SIGTSTP
```

#### `kill -1`

```bash
kill -1 PID
```

Sends **SIGHUP**.

Commonly used to reload configuration or notify a process that the session has closed.

#### `kill -9`

```bash
kill -9 PID
```

Sends **SIGKILL**.

* Immediately terminates the process.
* Cannot be caught or ignored by the process.
* Use when normal termination does not work.

#### `kill -15`

```bash
kill -15 PID
```

Sends **SIGTERM**.

* Requests the process to terminate gracefully.
* Allows the application to perform cleanup.
* Generally preferred before `kill -9`.

#### `kill -20`

```bash
kill -20 PID
```

Sends **SIGTSTP**.

* Stops/suspends a process.
* Similar to pressing `Ctrl + Z` for a foreground process.

---

### `killall`

Kills processes by process name instead of PID.

```bash
killall nginx
```

## Monitoring Commands

### `top`

`top` provides **real-time monitoring** of processes and system resources.

```bash
top
```

Unlike `ps`, `top` continuously refreshes the process information.

### Important `top` Fields

```text
PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
```

| Field     | Description                 |
| --------- | --------------------------- |
| `PID`     | Process ID                  |
| `USER`    | User who owns the process   |
| `PR`      | Process priority            |
| `NI`      | Nice value                  |
| `VIRT`    | Total virtual memory used   |
| `RES`     | Physical RAM currently used |
| `SHR`     | Shared memory               |
| `S`       | Process state               |
| `%CPU`    | CPU utilization             |
| `%MEM`    | Memory utilization          |
| `TIME+`   | Total CPU time used         |
| `COMMAND` | Process/command name        |

The upper section of `top` also displays:

```text
load average
CPU usage
memory usage
swap usage
```

Useful keys inside `top`:

```text
P  → Sort by CPU usage
M  → Sort by memory usage
k  → Kill a process
r  → Change process priority
q  → Quit top
```

---

### `htop`

`htop` is an interactive and user-friendly alternative to `top`.

```bash
htop
```

It provides:

* Real-time process monitoring
* CPU and memory usage
* Process sorting
* Process searching
* Process management

---

## Process Priority

Linux uses a **nice value** to control process priority.

* Nice value range: `-20` to `19`
* Lower nice value → Higher priority
* Higher nice value → Lower priority
* Default nice value → `0`

### `nice`

Starts a new process with a specified nice value.

```bash
nice -n 10 command
```

Example:

```bash
nice -n 10 ./script.sh
```

### `renice`

Changes the nice value of an already running process.

```bash
renice 10 -p PID
```

Example:

```bash
renice 10 -p 1250
```

## Zombie & Orphan Process

### Zombie Process

A **zombie process** is a process that has finished execution, but its parent has not yet collected its exit status.

State:

```text
Z
```

Check using:

```bash
ps -ef
```

or:

```bash
ps aux
```

### Orphan Process

An **orphan process** is a child process whose parent process has terminated.

The orphan process is adopted by **PID 1** (normally `systemd` on modern Linux systems).

Check using:

```bash
ps -ef
```

 <h1 align="center"> Job Control</h1>


Job Control allows us to manage foreground and background jobs from the terminal.

### 1. Foreground Job

A foreground job runs directly in the terminal and occupies it until the command finishes or is stopped.

Example:

```bash
ping google.com
````

### 2. Background Job

A background job runs without occupying the terminal, allowing you to execute other commands.

Example:

Bash

```
ping google.com &
```

### 3. `jobs`

Displays background and stopped jobs in the current shell.

Bash

```
jobs
```

Example:

```
[1]+  Running    ping google.com &
[2]-  Stopped    vim test.txt
```

### 4. `bg`

Resumes a stopped job in the background.

Bash

```
bg %1
```

Here, `%1` refers to job number 1.

### 5. `fg`

Brings a background or stopped job to the foreground.

Bash

```
fg %1
```

### 6. `Ctrl + Z`

Suspends the currently running foreground job.

The job can later be resumed using `fg` or `bg`.

### 7. `Ctrl + C`

Terminates the currently running foreground process by sending the `SIGINT` signal.

### 8. `&`

Runs a command in the background.

Bash

```
sleep 100 &
```

The terminal becomes available for executing other commands.

### 9. `nohup`

Runs a command so that it can continue running after the terminal is closed or the user logs out.

Bash

```
nohup ./script.sh &
```

By default, output is redirected to `nohup.out`.

Note: `nohup` prevents the command from being terminated by `SIGHUP`. It does not automatically place a command in the background; `&` does that.
