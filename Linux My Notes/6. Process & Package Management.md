# 1. Process Management


## What is a Process?

A **process** is a program that is currently running.

Example:

When we start Nginx:

```bash
systemctl start nginx
```

Nginx starts running as a **process** and gets a unique PID.

---

## Process States

A process can be in different states:

* **R → Running** – Process is currently running or ready to run.
* **S → Sleeping** – Process is waiting for something.
* **D → Uninterruptible Sleep** – Usually waiting for I/O.
* **T → Stopped** – Process has been stopped.
* **Z → Zombie** – Process has finished but its parent has not collected its exit status.

Check process states:

```bash
ps -ef
```

---

## PID and PPID

### PID

**PID (Process ID)** is the unique number assigned to a process.

```bash
ps -ef
```

Example:

```text
root    1234    1    nginx
```

Here `1234` is the PID.

### PPID

**PPID (Parent Process ID)** is the PID of the process that started the current process.

Here:

```text
PID     PPID
1234     1
```

Process `1234` was started by process `1`.

---

## Foreground vs Background Processes

### Foreground Process

A foreground process runs directly in the terminal and keeps the terminal occupied.

Example:

```bash
ping google.com
```

The terminal remains occupied by the `ping` process.

Press:

```text
Ctrl + C
```

to stop it.

### Background Process

A background process runs without occupying the terminal.

Use `&`:

```bash
ping google.com &
```

Now you can continue using the terminal.

---

## `ps` Command

`ps` is used to **view running processes**.

```bash
ps
```

Show all processes:

```bash
ps -ef
```

Example:

```text
UID      PID   PPID  CMD
root     1234    1   nginx
```

Common command:

```bash
ps -ef | grep nginx
```

---

## `top` Command

`top` is used to **monitor processes in real time**.

```bash
top
```

It shows:

* CPU usage
* Memory usage
* PID
* Process owner
* Running processes

Press `q` to exit.

---

## `htop` Command

`htop` is an **interactive and more user-friendly alternative to `top`**.

```bash
htop
```

It allows us to:

* View processes
* Sort processes
* Search processes
* Kill processes

It may need to be installed separately.

---

## `pgrep` Command

`pgrep` is used to find the **PID of a process by its name**.

```bash
pgrep nginx
```

Example output:

```text
1234
```

This means the Nginx process has PID `1234`.

---

## `pidof` Command

`pidof` is also used to find the **PID of a running program**.

```bash
pidof nginx
```

Example:

```text
1234 1250
```

It can return multiple PIDs if multiple processes are running.

### `pgrep` vs `pidof`

```text
pgrep → searches processes by name/pattern
pidof → finds PIDs of a specific program
```

---

## `pstree` Command

`pstree` displays processes in a **parent-child tree structure**.

```bash
pstree
```

Example:

```text
systemd
 ├── sshd
 │    └── bash
 └── nginx
      ├── nginx
      └── nginx
```

It helps us understand **which process started another process**.

---

## `jobs` Command

`jobs` shows the **background and stopped jobs of the current shell**.

Example:

```bash
ping google.com &
```

Then:

```bash
jobs
```

Output:

```text
[1]+  Running    ping google.com &
```

---

## `bg` and `fg`

### `bg`

`bg` resumes a stopped job in the **background**.

First press:

```text
Ctrl + Z
```

Then:

```bash
bg
```

### `fg`

`fg` brings a background job to the **foreground**.

```bash
fg
```

For a specific job:

```bash
fg %1
```

---

## `nohup`

`nohup` allows a process to continue running even after the terminal/session is closed.

Example:

```bash
nohup ./script.sh &
```

By default, output is generally written to:

```text
nohup.out
```

Common use:

```bash
nohup ./backup.sh > backup.log 2>&1 &
```

---

## `kill` and `killall`

### `kill`

`kill` sends a signal to a process using its PID.

```bash
kill 1234
```

By default, it sends **SIGTERM (15)**.

Forcefully terminate:

```bash
kill -9 1234
```

### `killall`

`killall` kills processes by **process name**.

```bash
killall nginx
```

> `kill` → uses PID
> `killall` → uses process name

---

## Process Priority

Linux assigns a **priority** to processes.

The `nice` value is used to influence process priority.

* Lower nice value → higher priority
* Higher nice value → lower priority

Normal nice value:

```text
0
```

---

## `nice` and `renice`

### `nice`

Used to start a process with a specific nice value.

```bash
nice -n 10 ./script.sh
```

This starts the process with a nice value of `10`, giving it lower CPU priority than the default.

### `renice`

Used to **change the nice value of an already running process**.

```bash
renice 10 -p 1234
```

Here, PID `1234` is assigned a nice value of `10`.

---

## Zombie Process

A **zombie process** is a process that has finished execution but its parent has not yet collected its exit status.

It remains in the process table.

State:

```text
Z
```

Check:

```bash
ps -ef
```

---
