<h1 align="center"> Process Management</h1>


### What is a Process?

A **process** is a running instance of a program.

Example:

```bash
nginx
````

When Nginx is running, Linux creates a process for it and assigns a **PID (Process ID)**.

---

### Types of Processes

#### 1. Interactive Process

A process started and controlled directly by a user.

Example:

```bash
vim test.txt
```

The process is connected to the user's terminal.

#### 2. System / Daemon Process

A process that runs in the background and provides system or application services.

Examples:

```text
sshd
cron
systemd
nginx
```

Daemon processes normally do not require direct user interaction.

#### 3. Automatic Process

A process that runs automatically based on a schedule, event, or system requirement.

Example:

```text
cron job
```

---

### Process States

| State | Meaning               |
| ----- | --------------------- |
| `R`   | Running               |
| `S`   | Sleeping              |
| `D`   | Uninterruptible Sleep |
| `T`   | Stopped               |
| `Z`   | Zombie                |

Check process state:

```bash
ps -ef
```

---

### PID & PPID

**PID (Process ID)**
Unique ID assigned to each process.

**PPID (Parent Process ID)**
PID of the process that created the current process.

Example:

```text
PID    PPID
2500   1200
```

Here, process `2500` was created by process `1200`.

## Static / One-Time Commands

### `ps`

`ps` displays information about currently running processes.

| Command | Description |
|---|---|
| `ps` | Displays processes associated with the current terminal. |
| `ps -a` | Shows processes associated with terminals for all users, excluding processes without a terminal. |
| `ps -u` | Displays processes in a user-oriented format. |
| `ps -u ubuntu` | Displays processes owned by the specific user `ubuntu`. |
| `ps -x` | Shows processes owned by the current user, including processes without a controlling terminal. |
| `ps aux` | Displays processes for all users in a detailed format, including CPU and memory usage. |
| `ps -ef` | Shows all processes in full-format listing, including PID and PPID. |
| `ps -e` | Displays all processes. `-e` means every process. |
| `ps -eo pid,ppid,user,stat,cmd` | Displays all processes with only the specified fields: PID, PPID, user, status, and command. |
| `ps -ef \| grep nginx` | Searches for processes containing `nginx` in the full-format process listing. |
| `ps -e \| wc -l` | Counts the lines in the process listing. The result includes the header line. |
| `echo $$` | Displays the PID of the current shell. |

### Common Fields in `ps aux`

| Field | Description |
|---|---|
| `USER` | Owner of the process |
| `PID` | Process ID |
| `%CPU` | CPU usage |
| `%MEM` | Memory usage |
| `VSZ` | Virtual memory size |
| `RSS` | Physical memory currently occupied |
| `STAT` | Process state |
| `START` | Process start time or date |
| `TIME` | Total CPU time used |
| `COMMAND` | Command used to start the process |

### Example: `ps -eo pid,ppid,user,stat,cmd`

```text
PID   PPID  USER    STAT  CMD
1     0     root    S     /sbin/init
1200  1     root    S     sshd
1250  1200  ubuntu  S     bash
```


### `ps -f` Field Description

```bash
ps -f
```

Example:

```text
UID      PID   PPID  C  STIME  TTY      TIME     CMD
ubuntu  1250   1200  0  18:20  pts/0    00:00:00 bash
```

| Field   | Description                          |
| ------- | ------------------------------------ |
| `UID`   | User who owns the process            |
| `PID`   | Process ID                           |
| `PPID`  | Parent Process ID                    |
| `C`     | CPU utilization value                |
| `STIME` | Process start time                   |
| `TTY`   | Terminal associated with the process |
| `TIME`  | CPU time used by the process         |
| `CMD`   | Command used to start the process    |


### `pgrep`

Finds PID(s) of a process using its name or pattern.

```bash
pgrep nginx
```

Example:

```text
1250
1260
```

### `pidof`

Displays PID(s) of a specific running program.

```bash
pidof nginx
```

Example:

```text
1250 1260
```

### `pstree`

Displays processes in a parent-child tree structure.

```bash
pstree
```

Example:

```text
systemd
 ├─sshd
 │  └─bash
 │     └─sleep
 └─cron
```

### `kill`

`kill` is used to send a signal to a process.

**Syntax:**

```bash
kill [signal] PID
````

| Command        | Description                                                                                                                                          |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kill -l`      | Lists available signals.                                                                                                                             |
| `kill -1 PID`  | Sends **SIGHUP**. Commonly used to reload configuration or notify a process that the session has closed.                                             |
| `kill -9 PID`  | Sends **SIGKILL**. Immediately terminates the process. Cannot be caught or ignored by the process. Use when normal termination does not work.        |
| `kill -15 PID` | Sends **SIGTERM**. Requests the process to terminate gracefully and allows the application to perform cleanup. Generally preferred before `kill -9`. |
| `kill -20 PID` | Sends **SIGTSTP**. Stops/suspends a process, similar to pressing `Ctrl + Z` for a foreground process.                                                |

### Common Signals

| Signal Number | Signal Name | Description                                    |
| ------------- | ----------- | ---------------------------------------------- |
| `1`           | `SIGHUP`    | Hangup; commonly used to reload configuration. |
| `2`           | `SIGINT`    | Interrupts a process.                          |
| `9`           | `SIGKILL`   | Immediately terminates a process.              |
| `15`          | `SIGTERM`   | Requests graceful termination.                 |
| `20`          | `SIGTSTP`   | Suspends a process.                            |


### `killall`

`killall` is used to kill processes by process name instead of PID.

```bash
killall nginx
```

| Command            | Description                                                |
| ------------------ | ---------------------------------------------------------- |
| `killall nginx`    | Terminates processes matching the name `nginx`.            |
| `killall -9 nginx` | Forcefully terminates processes matching the name `nginx`. |

## Monitoring Commands

### `top`

`top` provides **real-time monitoring** of processes and system resources.

```bash
top
```

Unlike `ps`, `top` continuously refreshes the process information.

### Important `top` Fields

```text
PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
```

| Field     | Description                 |
| --------- | --------------------------- |
| `PID`     | Process ID                  |
| `USER`    | User who owns the process   |
| `PR`      | Process priority            |
| `NI`      | Nice value                  |
| `VIRT`    | Total virtual memory used   |
| `RES`     | Physical RAM currently used |
| `SHR`     | Shared memory               |
| `S`       | Process state               |
| `%CPU`    | CPU utilization             |
| `%MEM`    | Memory utilization          |
| `TIME+`   | Total CPU time used         |
| `COMMAND` | Process/command name        |

The upper section of `top` also displays:

```text
load average
CPU usage
memory usage
swap usage
```

Useful keys inside `top`:

```text
P  → Sort by CPU usage
M  → Sort by memory usage
k  → Kill a process
r  → Change process priority
q  → Quit top
```

---

### `htop`

`htop` is an interactive and user-friendly alternative to `top`.

```bash
htop
```

It provides:

* Real-time process monitoring
* CPU and memory usage
* Process sorting
* Process searching
* Process management

## Process Priority

Linux uses a **nice value** to control process priority.

* Nice value range: `-20` to `19`
* Lower nice value → Higher priority
* Higher nice value → Lower priority
* Default nice value → `0`

### `nice`

Starts a new process with a specified nice value.

```bash
nice -n 10 command
```

Example:

```bash
nice -n 10 ./script.sh
```

### `renice`

Changes the nice value of an already running process.

```bash
renice 10 -p PID
```

Example:

```bash
renice 10 -p 1250
```

## Zombie & Orphan Process

### Zombie Process

A **zombie process** is a process that has finished execution, but its parent has not yet collected its exit status.

State:

```text
Z
```

Check using:

```bash
ps -ef
```

or:

```bash
ps aux
```

### Orphan Process

An **orphan process** is a child process whose parent process has terminated.

The orphan process is adopted by **PID 1** (normally `systemd` on modern Linux systems).

Check using:

```bash
ps -ef
```

 <h1 align="center"> Job Control</h1>


Job Control allows us to manage foreground and background jobs from the terminal.

### Foreground Job

A foreground job runs directly in the terminal and occupies it until the command finishes or is stopped.

Example:

```bash
ping google.com
````

### Background Job

A background job runs without occupying the terminal, allowing you to execute other commands.

Example:

Bash

```
ping google.com &
```
---

### `jobs`

Displays background and stopped jobs in the current shell.

Bash

```
jobs
```

Example:

```
[1]+  Running    ping google.com &
[2]-  Stopped    vim test.txt
```

###  `bg`

Resumes a stopped job in the background.

Bash

```
bg %1
```

Here, `%1` refers to job number 1.

###  `fg`

Brings a background or stopped job to the foreground.

Bash

```
fg %1
```
---
###  `Ctrl + Z`

Suspends the currently running foreground job.

The job can later be resumed using `fg` or `bg`.

###  `Ctrl + C`

Terminates the currently running foreground process by sending the `SIGINT` signal.

###  `&`

Runs a command in the background.

Bash

```
sleep 100 &
```

The terminal becomes available for executing other commands.
---

###  `nohup`

Runs a command so that it can continue running after the terminal is closed or the user logs out.

Bash

```
nohup ./script.sh &
```

By default, output is redirected to `nohup.out`.

Note: `nohup` prevents the command from being terminated by `SIGHUP`. It does not automatically place a command in the background; `&` does that.

<h1 align="center"> Package Management</h1>

Package management in Linux is used to **install, remove, update, query, and maintain software packages** in Linux.

On RHEL/CentOS-based systems, commonly used package management tools are:

RPM → Works directly with .rpm package files.
YUM → Works with repositories and automatically handles dependencies.
---

# RPM

**RPM (Red Hat Package Manager)** is a low-level package management tool used to manage `.rpm` packages.

### Common RPM Options

| Option | Meaning | Purpose |
|---|---|---|
| `-i` | Install | Install a new package |
| `-U` | Upgrade | Upgrade an installed package or install it if not present |
| `-e` | Erase | Remove a package |
| `-q` | Query | Query package information |
| `-V` | Verify | Verify package files |
| `-a` | All | Used with `-q` to query all installed packages |
| `-v` | Verbose | Display detailed output |
| `-h` | Hash | Show installation progress |

### Install Package

```bash
rpm -ivh package.rpm
````

| Option | Explanation    |
| ------ | -------------- |
| `-i`   | Install        |
| `-v`   | Verbose output |
| `-h`   | Show progress  |

Example:

```bash
rpm -ivh nginx.rpm
```

### Remove Package

```bash
rpm -e nginx
```

* `-e` → Erase/remove package

### Upgrade Package

```bash
rpm -Uvh package.rpm
```

* `-U` → Upgrade
* `-v` → Verbose
* `-h` → Show progress

### Query Package

```bash
rpm -q nginx
```

* `-q` → Query

Checks whether the package is installed and displays its version.

### Verify Package

```bash
rpm -V nginx
```

* `-V` → Verify

Checks whether installed package files have been modified or changed.

### List Installed Packages

```bash
rpm -qa
```

* `-q` → Query
* `-a` → All

To search for a specific package:

```bash
rpm -qa | grep nginx
```

---

# YUM

**YUM (Yellowdog Updater Modified)** is a high-level package manager used to install, remove, update, and manage packages from configured repositories.

Unlike RPM, **YUM automatically handles package dependencies**.

> On newer RHEL-based systems, **DNF** is the modern package manager, while `yum` is often provided as a compatibility command.

### Install Package

```bash
yum install nginx
```

Install without asking for confirmation:

```bash
yum install -y nginx
```

| Option    | Explanation              |
| --------- | ------------------------ |
| `install` | Install a package        |
| `-y`      | Automatically answer yes |

### Remove Package

```bash
yum remove nginx
```

or:

```bash
yum erase nginx
```

| Command  | Explanation              |
| -------- | ------------------------ |
| `remove` | Remove a package         |
| `erase`  | Same purpose as `remove` |

### Update Package

Update a specific package:

```bash
yum update nginx
```

Update all installed packages:

```bash
yum update
```

* `update` → Updates packages to newer available versions.

### Search Package

```bash
yum search nginx
```

Used when you **don't know the exact package name**.

Example:

```bash
yum search web server
```

YUM searches the available repositories for matching packages.

### List Packages

List installed packages:

```bash
yum list installed
```

List available packages:

```bash
yum list available
```

List all packages:

```bash
yum list all
```

| Command              | Purpose                                    |
| -------------------- | ------------------------------------------ |
| `yum list installed` | Shows installed packages                   |
| `yum list available` | Shows packages available from repositories |
| `yum list all`       | Shows installed and available packages     |

### Check Package Information

```bash
yum info nginx
```

Displays information such as:

* Package name
* Version
* Architecture
* Repository
* Size
* Description

### Clean Cache

```bash
yum clean all
```

Removes cached package and repository metadata.

This can be useful when troubleshooting **repository or package-cache issues**.

---

## RPM vs YUM

| RPM                                         | YUM                                                    |
| ------------------------------------------- | ------------------------------------------------------ |
| Low-level package manager                   | High-level package manager                             |
| Works directly with `.rpm` files            | Works with repositories                                |
| Does not automatically resolve dependencies | Automatically resolves dependencies                    |
| Useful for individual package management    | Useful for normal package installation and maintenance |
| `rpm -ivh nginx.rpm`                        | `yum install nginx`                                    |
