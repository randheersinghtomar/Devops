<h1 align="center">Module 6: Group Administration</h1>

## 1. What is Group Administration?

A **group** is a collection of users. It helps manage permissions for multiple users at once.

### Example

If `appuser1`, `appuser2`, and `appuser3` work on the same application, we can create an `appteam` group and give the group access to application files.





### Important Interview Point

A user's primary group is identified by the GID in `/etc/passwd`.

The fourth field of `/etc/group` lists supplementary members. It may be empty even when the group is a user's primary group.


---

## 2. Group Administration Commands

| Task | Command | Description |
|---|---|---|
| Create a group | `sudo groupadd appteam` | Creates a new group |
| View a group | `getent group appteam` | Displays group information |
| View all groups | `cat /etc/group` | Displays local groups |
| Rename a group | `sudo groupmod -n developers appteam` | Renames `appteam` to `developers` |
| Change GID | `sudo groupmod -g 2000 appteam` | Changes the group's ID |
| Delete a group | `sudo groupdel appteam` | Deletes a group |
| Check user's groups | `id appuser` | Shows the user's UID, GID, and groups |
| List group memberships | `groups appuser` | Displays groups the user belongs to |

---

## 3. Primary vs Secondary Groups

| Primary Group | Secondary Group |
|---|---|
| Main group of a user | Additional group membership |
| A user has one primary group at a time | A user can belong to multiple secondary groups |
| Usually used as the default group for new files | Provides additional access to shared resources |
| Primary GID is stored in `/etc/passwd` | Local supplementary memberships are listed in `/etc/group` |

### Example

```text
User: appuser
Primary Group: appuser
Secondary Group: appteam
```

### Easy Way to Remember

```text
Primary   = Main group
Secondary = Additional groups
```

## 4. Adding & Removing Users from Groups

| Task | Command |
|---|---|
| Add user to a group | `sudo usermod -aG appteam appuser` |
| Add user to multiple groups | `sudo usermod -aG appteam,developers appuser` |
| Remove user from a group | `sudo gpasswd -d appuser appteam` |
| Verify membership | `id appuser` |

### Important Interview Question

**What is the difference between `-G` and `-aG`?**

| `-G` | `-aG` |
|---|---|
| Replaces the existing supplementary group list | Adds a group while preserving existing supplementary groups |

### Remember

```text
-G  → Replace
-aG → Add without removing existing groups
```

Always use `-aG` when adding a user to a group without removing their existing memberships.

> **Note:** A user may need to log out and log back in for group changes to apply to their existing session.

## 5. GID & Group Files

**GID** stands for **Group ID**. It is the numeric identification number of a group.

### Important Group Files

| File | Purpose |
|---|---|
| `/etc/group` | Stores local group names, GIDs, and listed members |
| `/etc/gshadow` | Stores protected group information |
| `/etc/passwd` | Stores user information, including the primary GID |

### `/etc/group`

The `/etc/group` file contains local group information.

View the file:

```bash
cat /etc/group
```

Check a specific group:

```bash
grep '^appteam:' /etc/group
```

Or:

```bash
getent group appteam
```

### `/etc/group` Fields

Example:

```text
appteam:x:2000:appuser,appuser2
```

There are **4 fields**, separated by `:`.

```
appteam : x : 2000 : appuser,appuser2
   |     |     |           |
   |     |     |           └── Group members
   |     |     └────────────── GID
   |     └──────────────────── Password placeholder
   └────────────────────────── Group name
```

### Important Point

The fourth field contains **supplementary group members**.

It can be empty:

```text
appteam:x:2000:
```

This does not necessarily mean that nobody uses this group as a primary group.

### Check a User's Primary GID

```bash
id appuser
```

Example:

```text
uid=1001(appuser) gid=1001(appuser) groups=1001(appuser),2000(appteam)
```

Here:

```text
gid=1001(appuser) → Primary group
2000(appteam)     → Secondary group
```

## 6. Group Ownership

Every file has an **owner** and a **group owner**.

### Example

```bash
ls -l report.txt
```

Output:

```text
-rw-r--r-- 1 appuser appteam 1200 report.txt
```

Here:

```text
appuser → Owner
appteam → Group owner
```

### Group Ownership Commands

| Task | Command |
|---|---|
| Change group ownership | `sudo chgrp appteam report.txt` |
| Change user and group ownership | `sudo chown appuser:appteam report.txt` |
| Check file ownership | `ls -l report.txt` |
| Change group ownership recursively | `sudo chgrp -R appteam /opt/app` |

### Shared Directory for a Team

```bash
sudo mkdir -p /opt/app
sudo chown root:appteam /opt/app
sudo chmod 2770 /opt/app
```

The `2` in `2770` enables the **setgid bit**.

It makes new files and directories normally inherit the parent directory's group.

```text
/opt/app
    ↓
Group = appteam
    ↓
New files normally inherit appteam
```

## 7. Troubleshooting & Interview Questions

| Question | Answer |
|---|---|
| What is group administration? | Managing groups, users, and group-based permissions |
| Which command creates a group? | `groupadd` |
| Which command modifies a group? | `groupmod` |
| Which command deletes a group? | `groupdel` |
| What is a GID? | Numeric ID assigned to a group |
| Can a user have multiple primary groups? | No, one primary group at a time |
| What does `usermod -aG` do? | Adds supplementary group membership without replacing existing memberships |
| What does `chgrp` do? | Changes a file's group ownership |
| What happens to files when their group is deleted? | Files remain, but the GID may no longer map to a group name |
| Why might group changes not apply immediately? | The user's existing session may need to be refreshed |
