## 1. User Creation

## `useradd` vs `adduser`

### `useradd`

`useradd` is the standard Linux command used to create a user.

### Basic syntax

```bash
sudo useradd username
````

Example:

```bash
sudo useradd lokesh
```

Check the user:

```bash
id lokesh
```

Check the user's entry:

```bash
grep "^lokesh:" /etc/passwd
```

### `adduser`

On Debian/Ubuntu systems, `adduser` is a more user-friendly and interactive utility for creating users.

```bash
sudo adduser lokesh
```

It may interactively ask for:

* Password
* Full name
* Other user information

### Interview Point

> `useradd` is the lower-level command, while `adduser` is generally a more interactive/user-friendly utility available on Debian-based systems.

---

# Create a User with a Home Directory

Use `-m` to create the user's home directory.

```bash
sudo useradd -m testuser
```

Check the home directory:

```bash
ls -ld /home/testuser
```

Check the user:

```bash
id testuser
```

Check the `/etc/passwd` entry:

```bash
grep "^testuser:" /etc/passwd
```

### `-m`

```text
-m → Create the user's home directory
```

# Specify the Login Shell

Use `-s` to specify the user's login shell.

```bash
sudo useradd -m -s /bin/bash testuser
```

Check:

```bash
grep "^testuser:" /etc/passwd
```

Example:

```text
testuser:x:1001:1001::/home/testuser:/bin/bash
```

The last field is the user's login shell.

Common shells:

```text
/bin/bash
/bin/sh
/sbin/nologin
/bin/false
```

# Specify UID

Use `-u` to manually specify the user's UID.

```bash
sudo useradd -u 1500 -m testuser
```

Check:

```bash
id testuser
```

Example:

```text
uid=1500(testuser)
```

### Why specify a UID?

This can be useful during:

* Server migrations
* Application migrations
* Restoring applications
* Maintaining consistent file ownership
* Certain NFS/shared-storage environments

### Interview Question

**Q: What happens if two users have the same UID?**

Linux identifies file ownership using the UID rather than just the username.

Duplicate UIDs can therefore cause ownership and access confusion and should generally be avoided.

# Specify User Comment

Use `-c` to specify the user's comment/GECOS field.

```bash
sudo useradd -m -c "Linux Administrator" testuser
```

Check:

```bash
grep "^testuser:" /etc/passwd
```

Example:

```text
testuser:x:1001:1001:Linux Administrator:/home/testuser:/bin/bash
```

The comment/GECOS field can contain information such as:

* Full name
* Employee information
* User description

# Combine User Creation Options

In real administration, multiple options are commonly combined.

Example:

```bash
sudo useradd -m -u 1500 -s /bin/bash -c "Test Linux User" testuser
```

### Meaning

```text
-m
→ Create home directory

-u 1500
→ Set UID to 1500

-s /bin/bash
→ Set login shell

-c "Test Linux User"
→ Set comment/GECOS information
```

Verify:

```bash
id testuser
```

```bash
grep "^testuser:" /etc/passwd
```

# System / Service Users

A system user is generally created for running services or applications rather than for a human user.

Use `-r`:

```bash
sudo useradd -r nginxuser
```

Check:

```bash
id nginxuser
```

```bash
grep "^nginxuser:" /etc/passwd
```

## Service User with No Interactive Login

For a service account that should not have interactive login:

```bash
sudo useradd -r -s /usr/sbin/nologin nginxuser
```

Check:

```bash
grep "^nginxuser:" /etc/passwd
```

Example:

```text
nginxuser:x:998:998::/home/nginxuser:/usr/sbin/nologin
```

The exact UID and home-directory behavior can vary by Linux distribution and configuration.


## Why Use Service Accounts?

Applications should generally run using a dedicated account rather than `root`.

Examples:

```text
Nginx       → nginx user
MySQL       → mysql user
Jenkins     → jenkins user
Application → application-specific user
```

This follows the **principle of least privilege**.

### Interview Question

**Q: Why shouldn't applications normally run as root?**

Because if the application is compromised, an attacker could potentially gain root-level control of the system.

Using a dedicated service account limits the privileges available to the application.

# `/etc/skel`

`/etc/skel` contains default files that can be copied into a newly created user's home directory.

Check its contents:

```bash
ls -la /etc/skel
```

You may see:

```text
.bashrc
.bash_logout
.profile
```

When you create a user with a home directory:

```bash
sudo useradd -m testuser
```

the files from `/etc/skel` are typically copied into:

```text
/home/testuser/
```

Check:

```bash
ls -la /home/testuser
```

## Practical Use of `/etc/skel`

Suppose a company wants every new user's home directory to contain a standard configuration file.

You can place the required default file under:

```text
/etc/skel/
```

When a new user's home directory is created, the file can be copied there automatically.

### Important

`/etc/skel` is a template for **new users**.

Changing files in `/etc/skel` does **not automatically update existing users' home directories**.

## 2. User Information & Configuration

### 2.1 `id`

Shows information about a user such as UID, GID and groups.

```bash
id lokesh
````

Example:

```text
uid=1001(lokesh) gid=1001(lokesh) groups=1001(lokesh)
```

Useful options:

```bash
id -u lokesh        # Show UID
id -g lokesh        # Show primary GID
id -un lokesh       # Show username
```

---

### 2.2 `whoami`

Shows the username of the currently logged-in user.

```bash
whoami
```

Example:

```text
ubuntu
```

Useful when working with `sudo` or switching users.

---

### 2.3 `who`

Shows users currently logged into the system.

```bash
who
```

Example:

```text
ubuntu   pts/0   2026-09-19 09:20 (10.10.10.20)
```

Shows:

* Username
* Terminal
* Login time
* Source IP

---

### 2.4 `w`

Shows currently logged-in users along with what they are doing.

```bash
w
```

Example:

```text
USER     TTY      FROM          LOGIN@   IDLE   WHAT
ubuntu   pts/0    10.10.10.20  09:20    1:10   top
```

Useful for checking:

* Who is logged in
* Login time
* Idle time
* Current command/process

---

### 2.5 `last`

Shows historical user login information.

```bash
last
```

Example:

```text
ubuntu   pts/0   10.10.10.20   Fri Sep 19 09:20
ubuntu   pts/1   10.10.10.30   Thu Sep 18 18:10
```

Useful for:

* Checking previous logins
* Investigating login activity
* Checking reboot history

```bash
last reboot
```

# 2.6 `/etc/passwd`

Contains basic information about **local user accounts**.

View:

```bash
cat /etc/passwd
```

Example:

```text
lokesh:x:1001:1001::/home/lokesh:/bin/bash
```

Each line has **7 fields**:

```text
username:password:UID:GID:GECOS:home_directory:login_shell
```

Example:

```text
lokesh:x:1001:1001::/home/lokesh:/bin/bash
```

| Field          | Meaning                                      |
| -------------- | -------------------------------------------- |
| `lokesh`       | Username                                     |
| `x`            | Password information stored in `/etc/shadow` |
| `1001`         | UID                                          |
| `1001`         | Primary GID                                  |
| Empty          | GECOS/comment                                |
| `/home/lokesh` | Home directory                               |
| `/bin/bash`    | Login shell                                  |

### Useful command

```bash
getent passwd lokesh
```

This is preferred when checking the account through the system's configured user database sources.

---

# 2.7 `/etc/shadow`

Contains **password hashes and password aging information**.

View:

```bash
sudo cat /etc/shadow
```

Example:

```text
lokesh:$6$abc123$xxxxx:19800:0:99999:7:::
```

The file contains information such as:

* Password hash
* Last password change
* Minimum password age
* Maximum password age
* Warning period
* Account/password expiration information

### Important

`/etc/shadow` should be protected because it contains password hashes.

Check permissions:

```bash
ls -l /etc/shadow
```

Typical output:

```text
-rw-r----- 1 root shadow ... /etc/shadow
```

### `/etc/passwd` vs `/etc/shadow`

| File          | Purpose                            |
| ------------- | ---------------------------------- |
| `/etc/passwd` | Basic user/account information     |
| `/etc/shadow` | Password hashes and password aging |

---

# 2.8 `/etc/login.defs`

Contains **default configuration for user accounts and password aging**.

View:

```bash
cat /etc/login.defs
```

Useful settings include:

```text
UID_MIN
UID_MAX
SYS_UID_MIN
SYS_UID_MAX
PASS_MAX_DAYS
PASS_MIN_DAYS
PASS_WARN_AGE
CREATE_HOME
```

Example:

```bash
grep -E '^(UID_MIN|UID_MAX|PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE|CREATE_HOME)' /etc/login.defs
```

### Example meanings

```text
UID_MIN=1000
```

Starting UID range for normal users.

```text
PASS_MAX_DAYS=99999
```

Maximum password age.

```text
PASS_WARN_AGE=7
```

Warn the user 7 days before password expiration.

```text
CREATE_HOME=yes
```

Controls the default behavior related to home directory creation for user creation tools that consult this setting.

> Exact defaults can vary by distribution/version, so check the actual file on the server.

# 2.9 `/etc/default/useradd`

Contains default settings used by `useradd`.

View:

```bash
cat /etc/default/useradd
```

Example:

```text
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/sh
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
```

Important settings:

| Setting             | Meaning                                                        |
| ------------------- | -------------------------------------------------------------- |
| `HOME`              | Base directory for user home directories                       |
| `SHELL`             | Default login shell                                            |
| `SKEL`              | Skeleton directory                                             |
| `INACTIVE`          | Days after password expiration before account becomes inactive |
| `EXPIRE`            | Default account expiration date                                |
| `CREATE_MAIL_SPOOL` | Whether to create a mail spool                                 |

### Check `useradd` defaults

```bash
useradd -D
```

Example:

```text
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/sh
SKEL=/etc/skel
```

## 3. Password Management & Policy

Password management in Linux is used to:

- Set/change user passwords
- Control password expiry
- Force users to change passwords
- Enforce password complexity
- Control password history

---

## 3.1 `passwd`

`passwd` is used to **set or change a user's password**.

### Change your own password

```bash
passwd
````

Example:

```text
Changing password for ubuntu.
Current password:
New password:
Retype new password:
passwd: password updated successfully
```

### Change another user's password

As root/sudo:

```bash
sudo passwd lokesh
```

This allows an administrator to set a new password for `lokesh`.

### Check password status

```bash
sudo passwd -S lokesh
```

Example:

```text
lokesh P 09/19/2026 0 99999 7 -1
```

Common status:

| Status | Meaning            |
| ------ | ------------------ |
| `P`    | Password is set    |
| `L`    | Password is locked |
| `NP`   | No password        |

---

# 3.2 Password Aging & Expiry

Password aging controls **how long a password can be used**.

For example:

```text
Password expires after 90 days
Warning starts 7 days before expiry
```

Important settings:

```text
PASS_MAX_DAYS
PASS_MIN_DAYS
PASS_WARN_AGE
```

These can be configured in:

```bash
/etc/login.defs
```

Example:

```text
PASS_MAX_DAYS   90
PASS_MIN_DAYS   1
PASS_WARN_AGE   7
```

Meaning:

* `PASS_MAX_DAYS=90` → Password expires after 90 days
* `PASS_MIN_DAYS=1` → User must wait 1 day before changing it again
* `PASS_WARN_AGE=7` → Warning 7 days before expiry

> These are default policy values for account creation; existing users may have their own aging values.

---

# 3.3 `chage`

`chage` is used to **manage password aging for a specific user**.

### Check password aging

```bash
sudo chage -l lokesh
```

Example:

```text
Last password change                                    : Sep 19, 2026
Password expires                                        : Dec 18, 2026
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change         : 1
Maximum number of days between password change          : 90
Number of days of warning before password expires       : 7
```

This is a very important command for interviews.

---

## Set password expiry

```bash
sudo chage -M 90 lokesh
```

Meaning:

```text
-M 90
```

→ Password expires after 90 days.

---

## Set minimum password age

```bash
sudo chage -m 1 lokesh
```

→ User must wait 1 day before changing the password again.

---

## Set warning period

```bash
sudo chage -W 7 lokesh
```

→ User receives a warning 7 days before password expiry.

---

# 3.4 Force Password Change

Sometimes an administrator creates a user and wants the user to choose their own password during the first login.

Use:

```bash
sudo chage -d 0 lokesh
```

Now check:

```bash
sudo chage -l lokesh
```

You may see:

```text
Last password change : password must be changed
```

The user will be required to change the password.

### Another method

```bash
sudo passwd -e lokesh
```

`-e` expires the password immediately.

So:

```bash
sudo passwd -e lokesh
```

→ User must change the password at next login.

# 3.5 Password Complexity

Password complexity means requiring passwords to follow certain rules.

For example:

```text
Minimum length: 12
At least 1 uppercase letter
At least 1 lowercase letter
At least 1 number
At least 1 special character
```

On many Linux systems, this is handled through **PAM**.

A common module is:

```text
pam_pwquality
```

Configuration is commonly found in:

```bash
/etc/security/pwquality.conf
```

Example:

```text
minlen = 12
ucredit = -1
lcredit = -1
dcredit = -1
ocredit = -1
```

Meaning:

| Setting   | Meaning                             |
| --------- | ----------------------------------- |
| `minlen`  | Minimum password length             |
| `ucredit` | Uppercase requirement               |
| `lcredit` | Lowercase requirement               |
| `dcredit` | Digit requirement                   |
| `ocredit` | Other/special character requirement |

A negative value generally means **require at least that many**.

For example:

```text
ucredit = -1
```

→ Require at least 1 uppercase character.

> Exact PAM configuration can differ between distributions and versions.

---

# 3.6 PAM

**PAM = Pluggable Authentication Modules**

PAM provides a common authentication framework for Linux applications.

It can control things such as:

* Password authentication
* Password complexity
* Login restrictions
* Account restrictions
* Password changes

Common PAM configuration:

```bash
/etc/pam.d/
```

For example:

```bash
ls /etc/pam.d/
```

You may find configuration for:

```text
sshd
login
sudo
common-auth
common-password
```

### Simple flow

```text
User
  ↓
Application (SSH/login)
  ↓
PAM
  ↓
Authentication / Password Policy
  ↓
Allow or Deny
```

# 3.7 `pam_pwquality`

`pam_pwquality` is a PAM module used to **check password quality**.

It can enforce requirements such as:

```text
Password length
Uppercase
Lowercase
Numbers
Special characters
Password similarity
```

A common configuration is:

```bash
/etc/security/pwquality.conf
```

You can check whether it is being used in PAM configuration with:

```bash
grep -R "pam_pwquality" /etc/pam.d/
```

Example:

```text
password requisite pam_pwquality.so retry=3
```

Meaning the password quality check is performed and the user gets limited retry attempts.
