  <h1 align="center">1. User Creation</h1>

## <ins>Useradd vs Adduser</ins>

## 1. `useradd`

`useradd` is the standard Linux command used to create a user.

### Basic Syntax

```bash
sudo useradd username
````

## 2. `adduser`

On Debian/Ubuntu systems, `adduser` is a more user-friendly and interactive utility for creating users.

```bash
sudo adduser username
```

It may interactively ask for:

* Password
* Full name
* Other user information

### Interview Point

`useradd` is the lower-level command, while `adduser` is generally a more interactive/user-friendly utility available on Debian-based systems.

### Check the User

```bash
id username
```

## <ins>Create a User with a Home Directory, Login Shell, UID & User Comment</ins>


This is an entry from `/etc/passwd`. It contains basic information about a Linux user.

```text
testuser:x:1001:1001::/home/testuser:/bin/bash
```

There are **7 fields**, separated by `:`.

### Easy Way to Remember

```text
username : password : UID : GID : comment : User's home directory : shell
```

### Create User with Home Directory

```bash
sudo useradd -m testuser
```

Use `-m` to create the user's home directory.

### Specify Login Shell

```bash
sudo useradd -m -s /bin/bash testuser
```

Use `-s` to specify the user's login shell.

### Specify UID

```bash
sudo useradd -u 1500 -m testuser
```

Use `-u` to manually specify the user's UID.

### Specify User Comment

```bash
sudo useradd -m -c "Linux Administrator" testuser
```

Use `-c` to specify the user's comment/GECOS field.

### Check

```bash
id testuser
```


## Why Specify a UID?

This can be useful during:

* Server migrations
* Application migrations
* Restoring applications
* Maintaining consistent file ownership
* Certain NFS/shared-storage environments


## Comment/GECOS Field

The comment/GECOS field can contain information such as:

* Full name
* Employee information
* User description


# Combine User Creation Options

In real administration, multiple options are commonly combined.

### Example

```bash
sudo useradd -m -u 1500 -s /bin/bash -c "Test Linux User" testuser
```

| Option | Purpose                        |
| ------ | ------------------------------ |
| `-m`   | Create home directory          |
| `-d`   | Specify home directory         |
| `-s`   | Specify login shell            |
| `-u`   | Specify UID                    |
| `-c`   | Specify comment/GECOS          |
| `-r`   | Create system user             |
| `-M`   | Do not create home directory   |
| `-e`   | Set account expiration date    |
| `-f`   | Set password inactivity period |


## <ins> System / Service Users</ins>

A system user is generally created for running services or applications rather than for a human user.

## Create a System User

Use `-r`:

```bash
sudo useradd -r nginxuser
````

## Service User with No Interactive Login

For a service account that should not have interactive login:

```bash
sudo useradd -r -s /usr/sbin/nologin nginxuser
```

### Example

```text
nginxuser:x:998:998::/home/nginxuser:/usr/sbin/nologin
```

## Why Use Service Accounts?

Applications should generally run using a dedicated account rather than `root`.

### Examples

```text
Nginx       → nginx user
MySQL       → mysql user
Jenkins     → jenkins user
Application → application-specific user
```

This follows the **principle of least privilege**.


### Interview Question

**Q: Why shouldn't applications normally run as root?**

Because if the application is compromised, an attacker could potentially gain root-level control of the system.

Using a dedicated service account limits the privileges available to the application.

## <ins>  `/etc/skel`</ins>


`/etc/skel` contains default files that can be copied into a newly created user's home directory.

Check its contents:

```bash
ls -la /etc/skel
```

You may see:

```text
.bashrc
.bash_logout
.profile
```

When you create a user with a home directory:

```bash
sudo useradd -m testuser
```

the files from `/etc/skel` are typically copied into:

```text
/home/testuser/
```

Check:

```bash
ls -la /home/testuser
```

## Practical Use of `/etc/skel`

Suppose a company wants every new user's home directory to contain a standard configuration file.

You can place the required default file under:

```text
/etc/skel/
```

When a new user's home directory is created, the file can be copied there automatically.

### Important

`/etc/skel` is a template for **new users**.

Changing files in `/etc/skel` does **not automatically update existing users' home directories**.

Shows users currently logged into the system.

```bash

```

Example:


* Terminal

* Source IP

* Who is logged in
* Login time

* Checking previous logins

## <ins> `/etc/passwd`</ins>


Contains basic information about **local user accounts**.

View:

```bash
cat /etc/passwd
```

Example:

```text
lokesh:x:1001:1001::/home/lokesh:/bin/bash
```

Each line has **7 fields**:

```text
username:password:UID:GID:GECOS:home_directory:login_shell
```

Example:

```text
lokesh:x:1001:1001::/home/lokesh:/bin/bash
```

| Field          | Meaning                                      |
| -------------- | -------------------------------------------- |
| `lokesh`       | Username                                     |
| `x`            | Password information stored in `/etc/shadow` |
| `1001`         | UID                                          |
| `1001`         | Primary GID                                  |
| Empty          | GECOS/comment                                |
| `/home/lokesh` | Home directory                               |
| `/bin/bash`    | Login shell                                  |

### Useful command

```bash
getent passwd lokesh
```

This is preferred when checking the account through the system's configured user database sources.

---


## <ins> `/etc/shadow`</ins>

Contains **password hashes and password aging information**.

View:

```bash
sudo cat /etc/shadow
````

Example:

```text
lokesh:$6$abc123$xxxxx:19800:0:99999:7:::
```

### `/etc/shadow` Fields

The format contains **9 fields**, separated by `:`.

```text
username:password:lastchange:min:max:warning:inactive:expire:reserved
```

| Field        | Description                                                     |
| ------------ | --------------------------------------------------------------- |
| `username`   | User account name                                               |
| `password`   | Encrypted password hash                                         |
| `lastchange` | Days since `01-01-1970` when password was last changed          |
| `min`        | Minimum number of days before password can be changed           |
| `max`        | Maximum number of days password is valid                        |
| `warning`    | Number of days before password expiry to warn the user          |
| `inactive`   | Number of days after password expiry before account is disabled |
| `expire`     | Date when the account expires, in days since `01-01-1970`       |
| `reserved`   | Reserved field                                                  |

### Example

```text
lokesh:$6$abc123$xxxxx:19800:0:99999:7:::
```

Meaning:

* `lokesh` → Username
* `$6$abc123$xxxxx` → Password hash
* `19800` → Last password change
* `0` → Password can be changed immediately
* `99999` → Password does not normally expire
* `7` → Warning starts 7 days before expiry
* Empty → No inactive period configured
* Empty → No account expiration date
* Empty → Reserved field

### Password Field Values

The **password field** can contain special values:

```text
::      → Field 2 is empty → no password set
*       → Login using password is disabled
!       → Password is locked
!!      → Password has never been set
```

Example:

```text
nginx:!:...
```

This means the password is **locked**, so the user cannot log in using a password.

### Important

`/etc/shadow` should be protected because it contains password hashes.

Check permissions:

```bash
ls -l /etc/shadow
```

Typical output:

```text
-rw-r----- 1 root shadow ... /etc/shadow
```
Only privileged users should be able to read this file.


### `/etc/passwd` vs `/etc/shadow`

| File          | Purpose                            |
| ------------- | ---------------------------------- |
| `/etc/passwd` | Basic user/account information     |
| `/etc/shadow` | Password hashes and password aging |

## <ins> `/etc/login.defs`</ins>


Contains **default configuration for user accounts and password aging**.

View:

```bash
cat /etc/login.defs
```

Useful settings include:

```text
UID_MIN
UID_MAX
SYS_UID_MIN
SYS_UID_MAX
PASS_MAX_DAYS
PASS_MIN_DAYS
PASS_WARN_AGE
CREATE_HOME
```

Example:

```bash
grep -E '^(UID_MIN|UID_MAX|PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE|CREATE_HOME)' /etc/login.defs
```

### Example meanings

```text
UID_MIN=1000
```

Starting UID range for normal users.

```text
PASS_MAX_DAYS=99999
```

Maximum password age.

```text
PASS_WARN_AGE=7
```

Warn the user 7 days before password expiration.

```text
CREATE_HOME=yes
```

Controls the default behavior related to home directory creation for user creation tools that consult this setting.

> Exact defaults can vary by distribution/version, so check the actual file on the server.

## 3.1 `passwd` — Set & Change Password

The `passwd` command is used to set or change a user's password.

### Change your own password

```bash
passwd
````

### Change another user's password

As root or with sudo:

```bash
sudo passwd lokesh
```

The administrator can set a new password without knowing the user's old password.


## 3.2 Check Password Status

Use:

```bash
sudo passwd -S lokesh
```

Example:

```text
lokesh P 2026-09-20 0 99999 7 -1
```

Important status values:

| Status | Meaning            |
| ------ | ------------------ |
| `P`    | Password is set    |
| `L`    | Password is locked |
| `NP`   | No password        |

The output also contains password-aging information.

---

# 3.3 Password Aging & expiry

Password aging controls **how long a password can be used**.

For example:

```text
Password expires after 90 days
User gets a warning 7 days before expiry
```

Important settings:

```text
PASS_MAX_DAYS
PASS_MIN_DAYS
PASS_WARN_AGE
```

These are commonly configured in:

```bash
/etc/login.defs
```

### Meaning

| Setting         | Meaning                                           |
| --------------- | ------------------------------------------------- |
| `PASS_MAX_DAYS` | Maximum number of days a password is valid        |
| `PASS_MIN_DAYS` | Minimum days before password can be changed again |
| `PASS_WARN_AGE` | Days before expiry to warn the user               |

Example:

```text
PASS_MAX_DAYS=90
PASS_MIN_DAYS=1
PASS_WARN_AGE=7
```

Means:

```text
Password valid for 90 days
        ↓
Warning starts 7 days before expiry
        ↓
Password expires
```

> These are default policy values. Individual users can have different settings.

---

# 3.4 `chage` — Manage Password Aging

`chage` is used to manage password expiry and aging for a **specific user**.

### `chage`

```bash
chage -m 10 -M 90 -w 10 -I 15 -E 2021-01-01 <username>
````

* `-m 10` → Minimum days
* `-M 90` → Maximum days
* `-w 10` → Warning period
* `-I 15` → Inactive period
* `-E 2021-01-01` → Expiry date

> **Note:** Sequence may be changed. All fields are not mandatory.


This is one of the most important commands for Linux administration.

## Check Password Aging

```bash
sudo chage -l lokesh
```

Example:

```text
Last password change                    : Sep 20, 2026
Password expires                        : Dec 19, 2026
Password inactive                       : never
Account expires                         : never
Minimum number of days between changes  : 1
Maximum number of days between changes  : 90
Number of days of warning               : 7
```

This command should be your **first check when investigating password-expiry problems**.


## Set Maximum Password Age

```bash
sudo chage -M 90 lokesh
```

Meaning:

```text
Password expires after 90 days
```

## Set Minimum Password Age

```bash
sudo chage -m 1 lokesh
```

Meaning:

```text
User must wait 1 day before changing the password again.
```

## Set Password Warning Period

```bash
sudo chage -W 7 lokesh
```

Meaning:

```text
User receives a warning 7 days before password expiry.
```

# 3.5 Force Password Change

Sometimes an administrator creates a user and wants the user to change the temporary password during the next login.

Use:

```bash
sudo chage -d 0 lokesh
```

or:

```bash
sudo passwd -e lokesh
```

Both make the password expire immediately.

Check:

```bash
sudo chage -l lokesh
```

You may see:

```text
Last password change : password must be changed
```

### Common real-world scenario

```text
Admin creates user
        ↓
Admin sets temporary password
        ↓
User logs in
        ↓
System forces password change
        ↓
User sets personal password
```

---

# 3.6 Lock & Unlock Password

Sometimes you want to prevent password-based authentication without deleting the user.

### Lock password

```bash
sudo passwd -l lokesh
```

or:

```bash
sudo usermod -L lokesh
```

Check:

```bash
sudo passwd -S lokesh
```

You should see:

```text
L
```

### Unlock password

```bash
sudo passwd -u lokesh
```

or:

```bash
sudo usermod -U lokesh
```

## Password Lock vs Account Expiration

These are different concepts.

### Password lock

```bash
passwd -l lokesh
```

→ Locks the password.

### Account expiration

```bash
sudo chage -E 2026-12-31 lokesh
```

→ Sets an expiration date for the **account**.

So remember:

```text
Password lock
    ↓
Password authentication is locked

Account expiration
    ↓
Account becomes expired after the specified date
```

# 3.7 Password Complexity

Password complexity means enforcing rules for passwords.

For example:

```text
Minimum length
Uppercase character
Lowercase character
Number
Special character
```

Example policy:

```text
Minimum 12 characters
At least 1 uppercase
At least 1 lowercase
At least 1 number
At least 1 special character
```

On Linux, password complexity is commonly enforced through **PAM**.

A common module is:

```text
pam_pwquality
```

# 3.8 `pam_pwquality`

`pam_pwquality` checks whether a new password meets the configured quality requirements.

Common configuration:

```bash
/etc/security/pwquality.conf
```

Example:

```text
minlen = 12
ucredit = -1
lcredit = -1
dcredit = -1
ocredit = -1
```

Meaning:

| Setting   | Meaning                             |
| --------- | ----------------------------------- |
| `minlen`  | Minimum password length             |
| `ucredit` | Uppercase requirement               |
| `lcredit` | Lowercase requirement               |
| `dcredit` | Digit requirement                   |
| `ocredit` | Special/other character requirement |

For example:

```text
ucredit = -1
```

→ Require at least one uppercase character.

# 3.9 Password History

Password history prevents users from repeatedly using their previous passwords.

For example:

```text
Old password: Welcome@123
        ↓
User changes password
        ↓
New password: Linux@123
        ↓
User tries Welcome@123 again
        ↓
Password rejected
```

On systems using PAM, password history can commonly be implemented using:

```text
pam_pwhistory
```

Configuration depends on the Linux distribution and PAM setup.

You may see configuration such as:

```text
remember=5
```

Meaning:

```text
Remember the previous 5 passwords
```

# 3.10 PAM

### PAM = Pluggable Authentication Modules

PAM is a framework used by Linux applications for authentication and account-related checks.

Common PAM directory:

```bash
/etc/pam.d/
```

Examples:

```text
/etc/pam.d/sshd
/etc/pam.d/login
/etc/pam.d/sudo
```

PAM can handle:

* Authentication
* Password changes
* Password complexity
* Account restrictions
* Login restrictions
* Password history

### Simple Flow

```text
User
  ↓
SSH / Login / Application
  ↓
PAM
  ↓
Authentication & Policy Checks
  ↓
Allow / Deny
```

| `chage -E DATE user` | Set account expiration      |

<h1 align="center">5. Lock, Unlock & Expiration</h1>

### 1. Lock / Unlock User

Used to prevent or allow a user from logging in.

### Lock User

```bash
sudo passwd -l john
````

or

```bash
sudo usermod -L john
```

Locks the user's password and prevents password-based login.

### Unlock User

```bash
sudo passwd -u john
```

or

```bash
sudo usermod -U john
```

Unlocks the user's password.

---

## 2. Password vs Account Expiration

### Password Expiration

Controls when the **password** needs to be changed.

Check password status:

```bash
sudo chage -l john
```

Example:

```bash
sudo chage -M 90 john
```

Password expires after 90 days.

### Account Expiration

Controls when the **user account itself** expires.

Example:

```bash
sudo usermod -e 2026-12-31 john
```

The account will expire on `2026-12-31`.

---

| Requirement                   | Command                      |
| ----------------------------- | ---------------------------- |

| Unlock user                   | `passwd -u john`             |
| Lock user                     | `usermod -L john`            |
| Unlock user                   | `usermod -U john`            |
| Set account expiration        | `usermod -e 2026-12-31 john` |
| Check password/account status | `chage -l john`              |

### Interview Point ⭐

* `passwd -l` / `usermod -L` → Lock the user's password
* `passwd -u` / `usermod -U` → Unlock the user's password
* Password expiration → Password needs to be changed
* Account expiration → User account becomes expired
